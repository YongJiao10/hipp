# Core Workflow Artifact Lineage

This document is the artifact-level source of truth for active core-workflow
products, including upstream products generated by external backends that are
not local numbered entrypoints. Use it with the step registry and per-run
`--step-manifest-out` JSON files to reconstruct exact run lineage.

Local execution status terms:

- `local_numbered_step`: produced by a maintained `scripts/core_workflow/NN_MM_*`
  entrypoint.
- `external_backend`: produced outside the local numbered workflow, then consumed
  as a required upstream artifact.
- `derived_presentation`: refreshable local presentation output from maintained
  intermediate artifacts.
- `utility`: generated by a non-numbered test or smoke utility.

## Traceability Rules

- Treat generated RouteA flat subject label files as required upstream
  artifacts. They are not naturally present inputs and are not produced by
  `03_02`.
- Treat the Lynch2024 NSI TSV/CSV as a required input contract with columns
  `subject,nsi`; `02_03` is expected to pass exactly 78 subjects at
  `nsi >= 0.43` unless the run manifest records an explicit override.
- Treat FASTANS/PFM priors under `external/FASTANS/resources/PFM/priors/Lynch2024/`
  as external local assets, not generated by Kong2022 RouteA. Maintained Lynch
  PFM evidence is the `03_04` per-subject hard-label output set under
  `outputs_hcp/work/cortex_pfm/sub-<id>/lynch2024/`, including the final
  `PFM_Lynch2024priors.dlabel.nii` and hard-label component time series.
- Treat `scripts/core_workflow/sge_argon/` as tracked backend assets for Argon
  execution. They are not local numbered entrypoints.
- For local numbered steps, prefer the emitted `--step-manifest-out` JSON as the
  run-specific lineage record. This document defines the maintained artifact
  families and expected evidence when a local manifest is absent.
- Smoke products under `outputs_hcp/smoke_runs/<run_id>/` are isolated test
  products and must not be cited as official full-cohort outputs.
- Treat the external HCP family map as a runtime input rather than a repository
  artifact. Cross-fitted labels use full concat FC intentionally and make no
  run-level independence claim; the exclusion unit is subject plus HCP family.
