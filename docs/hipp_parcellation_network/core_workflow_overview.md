# Core Workflow Overview

This document is the authoritative workflow surface for active hippocampal processing.

## Scope

- Active modality regime: T1w-only processing surface
- Public execution layer: `scripts/core_workflow/`
- Numbering convention: `NN_MM_<semantic_name>.py`
- Global order is encoded by `NN`, independent of branch names

Branch mainlines:

- `kong2019`
- `kong2022_routea`
- `kong2022_routea_17net`
- `kong2022_routea_ctxreg`
- `kong2022_routea_ctxdrop`
- `kong2022_routeb`
- `lynch2024_20net`
- `lynch2024_8net`

Within `kong2022`, RouteA, RouteA 17-net, RouteA cortex-regression, RouteA cortex-drop, and RouteB are treated as parallel mainlines. The Lynch2024 branches are NSI-filtered FASTANS/PFM comparison branches against Kong2022 RouteA, with separate shared inputs and group roots.

## Pipeline Stages

- `01_xx`: manifests, cohort and shared input preparation
- `02_xx`: HippUnfold run and output validation
- `03_xx`: cortex reference generation
- `04_xx`: hippocampal FC materialization
- `05_xx`: merged-canonical group atlas construction
- `06_xx`: label materialization, overview rendering, presentation outputs

Group atlas method families include intrinsic FC, network/ROI FC, WTA, and
`gradient-spectral`. The maintained presentation policy is fixed final `K=3`;
`05_02_run_group_atlas.py` defaults to evaluating `K=2..8` while using `--force-final-k 3`. The automatic K selector is still available through
`--auto-k` for diagnostics but is no longer the default display policy. Partial
correlation spectral branches are retired from public method choices.

`gradient-spectral` consumes aligned HippoMaps/BrainSpace gradient artifacts
written by `05_01_compute_hippomaps_gradients.py` under `--gradient-root`, then
clusters selected columns. For Kong2022 and Lynch2024 ROI-registry routes,
`05_01` computes raw G1-G5 from the column-wise z-scored group mean Fisher-z
vertex-to-ROI/component FC matrix using `GradientMaps(n_components=N,
kernel="pearson")`, aligns component order and sign within each route to the
`4mm/hemi_L` anchor when available, and writes only the aligned arrays. `05_02`
selects aligned G1-G3 by default (`--gradient-components 1,2,3`).

`06_04_render_hippomaps_gradient_products.py` renders the same continuous
gradient artifacts with `hippomaps.plotting.surfplot_canonical_foldunfold`,
`cmap="plasma"`, `tighten_cwindow=True`, `share="row"`, and
`color_bar="right"`. For `den=512`, it treats `512` as HippoMaps v2 in the
current Python process and disables `unfoldAPrescale`; no AP surfarea rescale is
used for 512-density figures. The renderer defaults to bilateral output and accepts `--hemis L` or
`--hemis R` for single-hemisphere files. Although left and right hemispheres are
fit independently upstream, `05_01` writes aligned arrays before `06_04` renders
them. `06_04` then applies a display-only cross-route alignment by default:
`routea` is the reference, each selected route/hemi/component is sign-flipped for
rendering when its Pearson correlation to the matching `routea` component is
negative, and the saved `05_01` arrays remain unchanged. Continuous-gradient
figures also use shared per-smoothing, per-component color ranges across the
rendered routes so RouteA, cortex-regression, cortex-drop, and RouteB panels are
visually comparable for paper figures. Bilateral figures are still assembled
from separate L/R HippoMaps renders so each side keeps its own EV labels.
Manifests record the `external/hippomaps` import path, commit, plotter support
settings, upstream gradient alignment provenance, display flip decisions, and
shared color ranges.

Canonical presentation outputs live under `outputs_hcp/present/`. All maintained
method overview PNGs are written to `outputs_hcp/present/overviews/`.
Supplementary continuous-gradient products live in `outputs_hcp/present/gradients/`,
and cortex panels live in `outputs_hcp/present/cortex_panels/`. Smoke tests stay
isolated under `outputs_hcp/smoke_runs/<run_id>/`.

The complete gradient-spectral and normalized-WTA cluster-to-cortex template renderer is `06_10_render_cluster_roi_strength_panels.py`. Gradient mode consumes saved `cluster_roi_profile.npy` Fisher-z matrices with shape `K x 400`; WTA mode consumes the existing vertex-level `normalized_top20_count` labels and treats the four most frequent networks as named pseudo-clusters. Both modes paint all Kong2022 parcels using a global symmetric `RdBu_r` scale across 2mm/4mm and L/R, write rows 2mm-L, 2mm-R, 4mm-L, and 4mm-R, and show bilateral L/R cortex in every panel. Gradient K=3 columns are validated as `Anterior`, `Body`, and `Posterior`; WTA produces separate canonical8 and family17 4x4 overviews. This full-template strength view is separate from the significance-filtered cluster panels generated by `06_03_build_cluster_cortex_panels.py`.
Directory names intentionally do not encode `t1only`, `present_fixedk`, or a
`10perc/full` presentation split.

`scripts/core_workflow/` is both:
- canonical public interface (`NN_MM_*`)
- active implementation home (`scripts/core_workflow/lib/*`)

Subject-level RouteA gradient-spectral K=3 and WTA products are intentionally
kept outside the group workflow in the sibling directory
`scripts/individual_workflow/`. Those entrypoints reuse core workflow helpers.
Computation outputs use the subject-first layout
`outputs_hcp/work/individual_atlas/sub-<id>/{gradient,wta}/<smoothing>/<hemi>/`,
with run metadata under `outputs_hcp/work/individual_atlas/_runs/`, while
per-subject presentation surface overviews live in
`outputs_hcp/present/overviews/individual/{gradient,wta}/`. See
`docs/hipp_parcellation_network/individual_workflow_routea_gradients_wta.md`.

RouteA reference construction has an explicit upstream label-generation dependency. The artifact-level contract for generated RouteA ArealMSHBM labels, local numbered-step products, presentation products, and required evidence is maintained in `docs/hipp_parcellation_network/core_workflow_artifact_lineage.md`.

The `kong2022_routea_17net` branch uses the original Kong2022 17 network families for cluster annotation and network profiles. It reuses `shared_inputs/routea`, `surface`, 400-ROI FC caches, and RouteA gradients, then writes only taxonomy-dependent group outputs under `outputs_hcp/work/group_atlas/routea_17net_full_k3_fisherz/`. Run `05_02_run_group_atlas.py` with `--route-tag routea_17net --network-taxonomy family17`; do not run `05_01` for a separate `routea_17net` gradient tree.

The `lynch2024_20net` and `lynch2024_8net` branches use the NSI-filtered FASTANS/PFM cohort from `02_03_build_lynch2024_nsi_manifest.py` (`nsi >= 0.43`, expected `n=78`). External priors live under `external/FASTANS/resources/PFM/priors/Lynch2024/`; `03_04_run_lynch2024_fastans_pfm.py` generates official per-subject hard-label PFM dlabel/dscalar assets and hard-label component time series under `outputs_hcp/work/cortex_pfm/sub-<id>/lynch2024/`; shared inputs live under `outputs_hcp/inputs/hcp/lynch2024_fast_pfm_t1only/shared_inputs/pfm_nsi043_78/`. `03_03_build_lynch2024_reference.py` writes an exact ordered Lynch20 reference containing 20 unique networks after excluding `Noise`, plus canonical8 merged references from `config/cross_atlas_network_merge.json`. The maintained downstream scope is `gradient-spectral` and `wta-top` only. For `gradient-spectral`, only the non-Noise Lynch20 component bank is used; BrainSpace receives the low-dimensional Lynch feature matrix as a full graph (`brainspace_sparsity=0.0`), and `lynch2024_8net` reuses that gradient bank while applying the merged canonical8 taxonomy downstream. In `05_02`, Lynch runs use `--profile-surface-root outputs_hcp/inputs/hcp/kong2022/shared_inputs/routea_ctxreg` so cluster profiles are computed with the same cluster-mean hippocampal time-series correlation used by Kong RouteA; this does not change the Lynch PFM FC, masks, references, or gradient inputs.

The formal `gradient-spectral` clustering affinity is `shifted-cosine`, defined
as `(1 + cosine_similarity) / 2` on surface-adjacent vertices. Group manifests
record `surface_affinity`, `affinity_description`, and connected-graph
diagnostics. Overview items record `surface_affinity`,
`affinity_description`, and `source_group_manifests`; filenames remain stable,
while the visible title identifies shifted-cosine.

The read-only release audit accepts exactly nine formal group branches: HCP
RouteA canonical8, RouteA family17, RouteA weighted-fisherz, Lynch20, and
Lynch8; plus Stanford HC, Stanford Symp, and their two weighted-fisherz
derivatives. Run it with:

```bash
/home/yojiao/.conda/envs/py314/bin/python scripts/core_workflow/audit_formal_gradient_spectral_release.py --repo-root "$PWD"
```

The formal refresh launcher is fixed at `--jobs 1` and preflights exact leaf
inputs before starting its sequential 19-stage worker:

```bash
/home/yojiao/.conda/envs/py314/bin/python scripts/core_workflow/run_formal_gradient_spectral_refresh.py --launch --repo-root "$PWD" --jobs 1
```

Do not execute that production launcher as part of code or documentation
verification. Any archive move for outputs using the misnamed taxonomy remains
blocked until the exact inventory and destination are shown to the user and the
user explicitly confirms them.

Network display colors are centralized in `config/hipp_network_style.json`. Group-atlas label materialization, hippocampal overviews, WTA long-axis profiles, and cortex panels load network colors from that single file; `config/cross_atlas_network_merge.json` is mapping-only and must not carry color overrides. Missing colors are treated as errors, not gray/blue fallback display colors. For the RouteA 17-net taxonomy, same-family A/B/C subnetworks use deliberately separated lightness and saturation levels so overview bars, profiles, and label-table colors remain distinguishable while preserving the parent family hue.

The `kong2022_routea_ctxreg` branch is an isolated RouteA derivative: `04_00_materialize_cortex_regressed_surface_timeseries.py` writes `shared_inputs/routea_ctxreg` with run-wise local cortex residualization before `04_01` and `04_02` materialize FC. It does not overwrite uncontrolled RouteA roots.

The `kong2022_routea_ctxdrop` branch is the matched RouteA local-cortex exclusion control. `04_01_materialize_kong2022_roi_fc.py --ctxdrop` keeps hippocampal time series unchanged, excludes valid cortex vertices within 20 mm separately for each hippocampal vertex before ROI averaging, and writes isolated FC caches plus smoothing-independent local cortex-neighbor diagnostics under `shared_inputs/routea_ctxdrop/sub-*/surface/local_cortex_neighbors/hemi_*/`. Its maintained downstream scope is `gradient-spectral` and `wta-top`, with group outputs in `outputs_hcp/work/group_atlas/routea_ctxdrop_full_k3_fisherz/`. The shared local-cortex-neighbor count surface overlay for ctxreg/ctxdrop is rendered by `06_07_render_ctxdrop_neighbor_counts.py` under `outputs_hcp/present/local_cortex_neighbors/`.

Active numbered steps no longer shell out to the legacy hippocampal/cortex runtime directories.
The active runtime boundary allows external assets and the Workbench executable
`software/workbench/bin_linux64/wb_command`, but not external helper code scripts.

## Traceability Contract

Each entrypoint can emit a standardized step manifest via `--step-manifest-out` with:

- `step_id`
- `workflow_branch`
- `upstream_step_ids`
- `input_artifacts`
- `output_artifacts`
- `command`
- `git_commit`

Use these manifests to reconstruct exact lineage for each generated artifact set.
