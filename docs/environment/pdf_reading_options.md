# PDF reading options for scientific literature

Research date: 2026-11-16 (America/Chicago). This note compares current first-party documentation and public source, without opening research PDFs, installing software, or changing agent policy.

## Findings

PDF understanding, a local file-reading tool, a reusable skill, and an interactive viewer are separate capabilities. A model API accepting PDFs does not establish that an agent session exposes a corresponding local PDF tool. Skills package instructions, resources, and optional scripts; the host supplies their executable capabilities. [OpenAI skill documentation](https://learn.chatgpt.com/docs/build-skills), [Claude Code tool documentation](https://code.claude.com/docs/en/tools-reference).

### OpenAI and Codex

The OpenAI Responses API can accept a PDF as `input_file`. With a vision-capable model, preprocessing supplies extracted text together with page images. The current API also supports a PDF image-detail setting. This is a server-side file-input capability; it is not documentation of a Codex local `Read` tool. [OpenAI file-input guide](https://developers.openai.com/api/docs/guides/file-inputs).

The public OpenAI skill named `pdf` recommends rendering PDF pages with Poppler and examining the resulting images, using `pdfplumber` or `pypdf` for extraction, and using `reportlab` when creating PDFs. Its name is `pdf`, rather than “PDF Viewer.” However, its repository now explicitly declares itself deprecated and directs readers to `openai/plugins` for current examples. Treat this skill as an official historical workflow example, not a current mandatory installation recommendation. [PDF skill](https://github.com/openai/skills/blob/main/skills/.curated/pdf/SKILL.md), [repository deprecation notice](https://github.com/openai/skills/blob/main/README.md).

The maintained public plugin examples include specialized PDF output workflows, such as converting a Data Analytics report to PDF. That skill concerns export and output inspection, rather than reading scientific papers. Current Codex public source also recognizes a primary-runtime `pdf` plugin for artifact creation and editing, but that registration alone does not reveal its PDF-reading implementation. The public sources inspected do not establish a universal native Codex PDF-reading tool. [Report-to-PDF skill](https://github.com/openai/plugins/blob/main/plugins/data-analytics/skills/build-report/report-to-pdf/SKILL.md), [primary-runtime artifact registration](https://github.com/openai/codex/blob/main/codex-rs/core-plugins/src/artifact_operation.rs).

Codex provides an image-viewing implementation for image-capable models; rendering selected PDF pages to images can therefore bridge local PDF files to visual analysis when that tool is exposed. The desktop product can show file previews, whereas the CLI has no visual file-preview or annotation interface. User-visible PDF preview and model ingestion should be described separately. [Codex image-tool source](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/view_image.rs), [official file-workflow documentation](https://learn.chatgpt.com/docs/artifacts-viewer).

Local observations on `idas-research-yojiao`: the installed executable reported `codex-cli 0.169.0`; `pdftotext` and `pdftoppm` resolved inside the `py314` environment. The supplied session tool catalog exposes shell execution and image viewing, and no PDF skill is listed in this session's available-skills catalog. These are observations about this session, not product-wide guarantees.

### Claude and Claude Code

Claude's API PDF support processes page images alongside extracted page text. This supports reasoning about diagrams, charts, and other visual content without requiring the caller to first convert the document into Markdown. [Anthropic PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support).

Claude Code's built-in `Read` tool explicitly supports PDFs. Current documentation says that it reads short PDFs whole; for documents longer than ten pages, it uses the `pages` parameter, with at most twenty pages per request. Page-range reading renders pages through `pdftoppm`, which must be installed and on `PATH`. The Agent SDK documents distinct whole-PDF and rendered-page output forms. Thus “native Read” means an integrated agent tool, not the absence of PDF preprocessing or local dependencies. [Claude Code Read tool](https://code.claude.com/docs/en/tools-reference#read-tool-behavior), [Agent SDK Read outputs](https://code.claude.com/docs/en/agent-sdk/python#read).

Anthropic also publishes a reusable skill named `pdf`, a general document-processing guide covering extraction, tables, manipulation, and OCR through Python packages and command-line tools. It is distinct from the built-in Read tool. [Anthropic PDF skill](https://github.com/anthropics/skills/blob/main/skills/pdf/SKILL.md).

There **is** an official Anthropic **PDF Viewer** plugin. Its skill is named `view-pdf`. It opens documents in an interactive viewer for collaborative highlights, annotations, forms, and visual signatures. Its instructions expressly route summarization, reading a page, and text/table extraction to native Read instead. The viewer uses a local MCP server, configured as `@modelcontextprotocol/server-pdf`; it is not a prerequisite for reading papers. [Viewer skill](https://github.com/anthropics/knowledge-work-plugins/blob/main/pdf-viewer/skills/view-pdf/SKILL.md), [plugin documentation](https://github.com/anthropics/knowledge-work-plugins/blob/main/pdf-viewer/README.md), [server configuration](https://github.com/anthropics/knowledge-work-plugins/blob/main/pdf-viewer/.mcp.json).

## Recommendation for this project

The existing policy uses one specific parser to create reusable Markdown/JSON literature packages. That solves repeated text ingestion and structured extraction. It does not by itself provide the visual evidence needed to interpret a plotted axis, a table's row/column alignment, or mathematical notation.

Use a two-part reading workflow: obtain searchable prose through the available native reader or an appropriate local extractor, then inspect the original pages that carry scientific evidence or uncertain structure. Reuse existing good extracted text for repeated searches. Visually inspect figures, tables, equations, and ambiguous multi-column passages when the answer depends on them; use OCR for scanned pages. A text extractor and a page renderer serve different purposes, so neither should be made a universal replacement for the other. This is a project recommendation derived from the documented text-plus-image approaches, not a vendor requirement. [OpenAI PDF input processing](https://developers.openai.com/api/docs/guides/file-inputs), [Anthropic PDF input processing](https://platform.claude.com/docs/en/build-with-claude/pdf-support), [OpenAI historical extraction/rendering guidance](https://github.com/openai/skills/blob/main/skills/.curated/pdf/SKILL.md).

There is no evidence in the inspected official sources that either vendor requires `opendataloader_pdf`. Keep it available where its structured output is useful; avoid requiring that particular package for every paper-reading question. An interactive viewer is useful when the user wants to view or annotate a paper together, and is optional for ingestion. This recommendation does not authorize migration or removal of existing literature artifacts. [OpenAI historical PDF workflow](https://github.com/openai/skills/blob/main/skills/.curated/pdf/SKILL.md), [Anthropic native Read](https://code.claude.com/docs/en/tools-reference#read-tool-behavior), [Anthropic viewer scope](https://github.com/anthropics/knowledge-work-plugins/blob/main/pdf-viewer/skills/view-pdf/SKILL.md).

Proposed tool-neutral policy wording:

> For PDF-backed reading, use the PDF reader available in the current agent environment, or a suitable local text/layout extractor. Reuse existing extracted text and metadata when suitable. Inspect original page images for figures, tables, equations, and passages whose layout or extraction is uncertain whenever the answer depends on them. Use OCR for scanned pages. Choose tools according to the document and task rather than requiring one parser universally. Preserve the project's literature organization and cite relevant source pages. Use an interactive viewer when collaborative viewing or annotation is requested.
