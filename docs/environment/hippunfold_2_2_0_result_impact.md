# HippUnfold 2.2.0 versus the retained 2.0.0 results

Assessed on 2026-10-22 from official release records, tagged source comparisons, current local workflow configuration, and an authorized paired pilot on HCP subjects 102311, 156334 and 878776. The pilot runs v2.2.0 scientific source in the existing hippo2 dependency environment with documented resource/runtime adaptations under `tmp/hippunfold_version_comparison/`. The pilot preceded the production upgrade. The approved v2.0.0 outputs and hippocampus-dependent products have since been moved under `wrong/outputs_<dataset>/`; independent cortical products remain active. The refreshed production runtime completed structural reconstruction for all 166 source-roster subjects. A full-cohort native-unfold mapping assessment on 2026-10-23 found right-sided correspondence conflicts in 11 subjects. [Measured version comparison](../../tmp/hippunfold_version_comparison/RESULTS.md), [complete-cohort mapping assessment](../../tmp/hcp7t_native_mapping_qc_20261023/README.md).

## Assessment

Recommendation: adopt v2.2.0 as the target scientific baseline and rebuild the cohort and dependent hippocampal analyses consistently. The upstream change addresses a documented limitation of the old thickness-estimation defaults, and the paired pilot establishes a material effect on the measurements. Retaining v2.0.0 solely to avoid rebuilding would preserve that known limitation. This is a methodological recommendation; the pilot measures differences, rather than accuracy against anatomical ground truth. [Official change and motivation](https://github.com/khanlab/hippunfold/pull/559).

Across the six subject/hemisphere pairs, mean vertex thickness increases by approximately 13–29%. Individual FC correlations span 0.950–0.9997 and normalized-top20-count vertex-network agreement spans approximately 77–98%. Three-subject group gradients retain absolute correlations of 0.975–0.999 and gradient-spectral K=3 partitions retain ARI of 0.980–1.000. The observed group stability is useful evidence about broad organization, while the individual differences justify regenerating dependent products during the upgrade. [Measured report](../../tmp/hippunfold_version_comparison/RESULTS.md).

An actual correspondence defect was observed in subject 102311: nine right-hemisphere atlas-grid vertices shift by more than 1 mm, reaching 13.13 mm in T1w coordinates. The native unfolded mesh has physically conflicting triangle correspondences at these targets; some ambiguity exists in the old result as well. Explicit unregistered resampling reproduces the primary coordinates and this hemisphere's unfolded registration is an identity in both outputs, so these particular shifts arise before unfolded registration and must not be attributed to the thickness-to-registration hypothesis. [Diagnostic figure and measurements](../../tmp/hippunfold_version_comparison/analysis/sub-102311/boundary_diagnostic/README.md).

## Why midthickness-only FC sampling can still change here

The native midthickness surface is not directly rewritten by the inner/outer registration. However, native thickness is calculated from inner and outer surfaces. Unfolded registration reads the metrics declared by the atlas, and fixed-density anatomical surfaces are then resampled using that registered unfolded mesh. [Thickness calculation](https://github.com/khanlab/hippunfold/blob/v2.2.0/hippunfold/workflow/rules/native_metrics.smk#L160-L209), [unfolded metric selection](https://github.com/khanlab/hippunfold/blob/v2.2.0/hippunfold/workflow/rules/unfold_reg.smk#L261-L296), [registered reference selection](https://github.com/khanlab/hippunfold/blob/v2.2.0/hippunfold/workflow/rules/native_resampling.smk#L1-L27), [fixed-density resampling](https://github.com/khanlab/hippunfold/blob/v2.2.0/hippunfold/workflow/rules/native_resampling.smk#L58-L124)

The actual saved completed HCP configuration for sub-102311 selects multihist7, unfolded registration enabled, and curvature, gyrification, **and thickness** as registration metrics. Therefore the following dependency is used in this project:

```text
inner/outer registration -> native thickness -> unfolded registration
-> 512-vertex anatomical midthickness -> BOLD sampling -> FC/gradients/parcels
```

The inspected sampling record consumes T1w midthickness surfaces with 512 vertices per hemisphere, transforms them to the HCP BOLD MNI frame, and uses trilinear point sampling with no smoothing iterations. It does not directly sample an inner/outer ribbon. The indirect registration dependency above still applies. This is evidence from one completed HCP configuration and sampling record, not an audit of every historical output. Local sources: [completed configuration](../../wrong/outputs_hcp/inputs/hippunfold/dense_corobl_batch/sub-102311/hippunfold/config/snakebids.yml), [consumed surface record](../../wrong/outputs_hcp/inputs/kong2022/shared_inputs/surface/sub-102311/surface/raw/surface_sampling_summary.json), [surface selection and sampling](../../scripts/core_workflow/lib/surface_sampling.py), [current launch contract](../../scripts/core_workflow/lib/hippunfold_run_contract.py).

Scientific interpretation: the pilot observes broadly similar group FC gradients alongside individual FC and assignment differences. Retaining the declared adult model and reference atlas is consistent with that broad stability, while local positions, boundary vertices, low-coverage locations, and parcels with closely competing connectivity profiles can change. The same 512 output density controls mesh size; it does not make the two versions numerically equivalent.

## Limits and practical decision

The current local environment documentation records nnUNet 1.7.1, while the unchanged upstream nnUNet v1 environment declaration pins the inference package at 1.6.6. A full upgrade therefore compares concrete environments as well as tagged workflow sources. The current local resource-resolution patches concern cached-resource handling; the environment name or stale package metadata alone cannot establish the effective algorithm version. [Local runtime manifest](hippo2_reproducibility_manifest.md), [upstream inference environment](https://github.com/khanlab/hippunfold/blob/v2.2.0/hippunfold/workflow/envs/nnunet.yaml)

The reviewed release notes, source diff, PR 559, and targeted official issue/PR searches supplied no official paired 2.0.0/2.2.0 quantitative benchmark. The local pilot now supplies measured thickness, displacement, FC, gradient and parcel-stability results for three subjects. Five were originally selected; after reviewing the first three, the user judged the observed differences sufficient and further reconstruction was stopped. The fourth subject's partial files are excluded and the fifth was not started. Inputs, model, density, preprocessing choices, BOLD, cortical references and downstream definitions were held fixed. CPU scheduling changed to accelerate the run and native mesh regeneration can vary, so the pilot does not assign every difference to a specific source edit. It also does not compare the full published Pixi dependency stack or replicate the 148-subject analysis. Existing baseline anatomical segmentation volumes were pruned before this experiment; template QC Dice is available, but direct between-version voxelwise segmentation overlap is not. [Runtime and exact methods](../../tmp/hippunfold_version_comparison/README.md).

The three completed comparisons are sufficient for the version-adoption decision; further pilot subjects are unnecessary for that purpose. The recommended migration sequence is:

1. Prepare the official v2.2.0 runtime, update the local environment gate and runtime documentation together, and verify GPU use for neural-network inference. Surface processing and registration retain their appropriate CPU execution.
2. Resolve the observed local unfolding/correspondence defect and check the affected existing pilot outputs before releasing rebuilt scientific results. This is a concrete quality issue in the measured surfaces, independent of the decision to adopt the thickness-method correction.
3. Rebuild the complete analysis cohort with v2.2.0 and regenerate products that consume the changed hippocampal assets: sampled hippocampal time series, FC, gradients, assignments, group results, statistics, and figures. Reuse unchanged anatomical inputs, fMRI preprocessing, and cortical references.
4. Retain the v2.0.0 results as comparison references during migration and follow the repository's exact-path approval requirements when replacing formal result trees.

### Official history of unfolding artifacts

The most directly relevant official report is [issue #498](https://github.com/khanlab/hippunfold/issues/498), which describes occasional native Laplace--Beltrami failures and investigates mesh holes and disconnected source/sink boundaries. Its surface-generation, boundary-connectivity and metric-normalization fixes are already included in both 2.0.0 and 2.2.0. The authors also tested a finer 0.2-mm internal hippocampal mesh, improving their test failures, while deliberately retaining the 0.3-mm default. This is a mechanism-specific experimental option, separate from output density, and is not a validated repair for the present 11 cases. The original HippUnfold paper describes manual inspection and correction or exclusion of erroneous results; HippoMaps uses HippUnfold 1.3.0 and does not prescribe a repair for the present candidate-ambiguity criterion. [Primary-source review](../../tmp/hcp7t_native_mapping_qc_20261023/upstream_research.md).

Upstream developers have discussed folded-over unfolded vertices and poor cotangent weights during the experimental vertex-spacing work in [PR 382](https://github.com/khanlab/hippunfold/pull/382). The subsequent [PR 414](https://github.com/khanlab/hippunfold/pull/414) removed spring/smoothing from the coordinate-registration path while retaining those surfaces for gyrification. This historical artifact is related in appearance, but is not a confirmed diagnosis of the current native Laplace–Beltrami conflict. An older [DG self-intersection report](https://github.com/khanlab/hippunfold/issues/241) concerns a different structure and a voxelization-related mechanism; its suggested denser DG sampling is not a validated repair for the current hippocampal mapping.

Before v2.0.0, upstream added joint AP/PD boundary assignment ([PR 377](https://github.com/khanlab/hippunfold/pull/377)), coordinate rank uniformization ([PR 429](https://github.com/khanlab/hippunfold/pull/429)), and connected-component relabeling ([PR 507](https://github.com/khanlab/hippunfold/pull/507)). These are already in the v2.0.0 baseline. Direct tagged-source comparison finds no change to the Laplace solve or uniformization mathematics in v2.2.0; changes there remove unused code and reorder imports. The boundary point-ID compatibility repair addresses newer PyVista behavior. Both versions use Workbench barycentric resampling through the native unfolded surface, without a dedicated physically conflicting-correspondence rejection or repair step in this path. [v2.0.0 solver](https://github.com/khanlab/hippunfold/blob/v2.0.0/hippunfold/workflow/scripts/laplace_beltrami.py), [v2.0.0 resampling](https://github.com/khanlab/hippunfold/blob/v2.0.0/hippunfold/workflow/rules/native_resampling.smk).

The complete production-cohort check covers all 166 subjects and 332 hemispheres. A target is counted when covering native unfolded triangles interpolate to candidate corobl positions more than 1 mm apart; this is a reporting criterion, not a measured anatomical error or an automatic exclusion rule. Exactly 11/166 subjects (6.63%) meet this definition, all on the right, with 98 conflicting subject/hemisphere/atlas-target combinations. No left hemisphere meets the criterion. Maximum candidate separation is 13.582873 mm. [Methods, complete tables and runnable analysis](../../tmp/hcp7t_native_mapping_qc_20261023/README.md).

All 11 affected subjects pass the current motion and bilateral Dice criteria: they account for 11/155 (7.10%) of the first-two-criterion passes. The remaining 144 first-two-criterion passes have no conflict under this definition; functional coverage remains a separate assessment. These measurements do not create a new exclusion policy. The production check reproduces the pilot findings for 102311 (0/14), 156334 (0/0) and 878776 (0/0). This is the measured frequency in the complete HCP7T source roster, not a population prevalence estimate. Stretching or a nonrectangular unfolded outline alone does not establish a defect; physically competing source positions are the consequential finding here.

A follow-up checks the actual `space-unfoldreg_den-native` inputs used by production resampling for all 332 hemispheres. They have identical coordinates to the unregistered unfolded meshes, and the same 11 right-sided cases and 98 target combinations are flagged. This confirms that the ambiguity also exists in the selected registration inputs, but does not establish which candidate was selected or its error against anatomical ground truth. The reporting criterion is not an official exclusion rule and the 98 findings are not 98 proven incorrect functional sampling nodes. [Registered-input results and interpretation](../../tmp/hcp7t_native_mapping_qc_20261023/upstream_research.md#important-qualification-of-our-current-11-person-finding).

Targeted diagnosis reproduces a defect in official terminal-label contiguity correction: individual stray vertices are reassigned using an unchanged original label map, and the final labels may remain or become more fragmented. All 11 ambiguous right hemispheres have disconnected PD terminals. In sub-102311, initial terminal component counts `[1,1,2,3]` become `[1,1,6,3]`, exactly reproducing the saved output. An isolated whole-component relabeling experiment changes 18 right-hemisphere label sets and leaves the other 148 unchanged. Recomputing the 18 changed cases plus one unchanged control removes all 98 sampled ambiguities, with the control reproducing its den-512 coordinates exactly. Residual reversed triangles and three newly uncovered edge targets remain, so this establishes a causal experimental result rather than formal repair approval. A matched official-resolution comparison on identical upstream artifacts gives 14 ambiguities at 0.3 mm and 13 at 0.2 mm; finer sampling alone does not fix the representative case. [Diagnosis, tables, reviewed limitations and figure](../../tmp/hcp7t_native_mapping_qc_20261023/boundary_diagnosis.md).

The refreshed-runtime 102311 test completes all 418 rules and retains every required output. Its consumed bilateral T1w surfaces each contain 512 finite vertices; template-agreement Dice is 0.76279/0.79944 (L/R). Checking all atlas targets finds 14 right targets with native-unfolded candidate physical positions more than 1 mm apart, reaching 13.46 mm; the earlier nine version-displacement outliers were a subset. No left target meets this conflict criterion. Candidate separation measures ambiguity, not anatomical error against ground truth.

Recomputing the official Laplace–Beltrami coordinates reproduces the saved rank-uniformized values to 3e-8. Physically conflicting mappings already exist before rank uniformization and before unfolded registration. An isolated experiment restricting labeling to the true mesh boundary does not remove the conflict, so that change is not adopted as a repair. The existing output check records the concrete native-unfolding conflict. Structural reconstruction and QC can proceed; this hemisphere's native mapping must be resolved before functional downstream use. Diagnostic experiments do not replace formal scientific outputs.

The user approved migration and the complete 166-person HCP7T structural rebuild, which has finished on IDAS. Every subject's output check records a completed 2.2.0 run. Subsequent cleanup removed the formal anat/coords/warps intermediates; the earlier full-output status must not be interpreted as their current availability. The archived v2.0.0 products remain the pilot baseline. The pi/argon reviewer found no blocking implementation issues and agreed to structural reconstruction/QC with functional release held pending correspondence resolution. Diagnosis and candidate-repair experiments remain in the temporary workspace; they do not replace formal surfaces, update subject output checks, alter analysis rosters or patch the installed scientific runtime.

Finally, current upstream `main` contains an additional unfolded-registration initialization repair after v2.2.0: geometric image centres replace intensity-weighted centres because signed curvature can destabilize initialization. That repair is **not included in v2.2.0** and must be evaluated separately if selecting a development revision.
