# HippUnfold v2.4.0: changes and implications for the v2.3.0 results

The official [v2.4.0 release](https://github.com/khanlab/hippunfold/releases/tag/v2.4.0) was published on 2026-11-01 at 19:38 UTC. It changes the surface reconstruction, unfolded registration, default atlas and the meaning of the output named `gyrification`. The existing v2.3.0 results are not automatically changed by a new release. A v2.4.0 rerun, however, can produce different surfaces, atlas correspondences, subfield labels and derived analyses. The magnitude for this project's participants has not been measured.

This assessment compares official upstream releases. The project's previous locally adapted v2.3.0 runtime and HCP results are described in the [runtime manifest](hippo2_reproducibility_manifest.md) and [result-impact assessment](hippunfold_result_impact.md). The local v2.4.0 implementation and its verification at that time are described below; the [runtime manifest](hippo2_reproducibility_manifest.md) specifies the current release.

## What stayed the same for the current T1w route

- Both tagged configurations specify the adult T1w model `Task101_hcp1200_T1w`, `nnUNetTrainerV2`, and `model_best`, using the same model record and archive name. Both use `CITI168` as the default anatomical template. The new lifespan model is a separately selected alternative, not the new T1w default. [v2.3.0 configuration](https://github.com/khanlab/hippunfold/blob/v2.3.0/hippunfold/config/snakebids.yml), [v2.4.0 configuration](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/config/snakebids.yml), [model PR #578](https://github.com/khanlab/hippunfold/pull/578).
- Both releases list `512` as a supported output density; both set `8k` as their upstream default. The project explicitly uses 512 and must continue to establish actual density from consumed surface assets. [v2.3.0 atlas plugin](https://github.com/khanlab/hippunfold/blob/v2.3.0/hippunfold/plugins/atlas.py), [v2.4.0 atlas plugin](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/plugins/atlas.py), [project runtime manifest](hippo2_reproducibility_manifest.md).

The matching model names and density option do not imply identical outputs: later scientific processing and the default atlas changed.

## Scientific changes

### Surface geometry and unfolded coordinates

- [PR #585](https://github.com/khanlab/hippunfold/pull/585) replaces the problematic native-mesh hole-filling sequence with repair, hole filling, repair, decimation and another repair, and adds stage-specific QC. The upstream investigation found that the earlier hole-filling operation introduced misoriented faces and, in one example, non-manifold elements. [PR #586](https://github.com/khanlab/hippunfold/pull/586) adds edge flips and constrained tangential relaxation to improve triangle quality.
- [PR #587](https://github.com/khanlab/hippunfold/pull/587) constrains the fitted terminal arcs on the boundary loop instead of fixing the whole two-ring boundary band, removes boundary chords and clamps negative cotangent weights. The former band constraints could collapse faces in unfolded space. [PR #588](https://github.com/khanlab/hippunfold/pull/588) adds monotonic boundary handling to reduce remaining folds. In the upstream ds002168 example, collapsed faces fell to zero across the four examined surfaces; some other defects remained. These are example results, not a guarantee for every participant.
- [PR #597](https://github.com/khanlab/hippunfold/pull/597) makes surface normals point from inner to outer independently of image handedness. The authors found that their in-vivo example already had this orientation while the histology inputs had the reverse orientation, which also reversed the sign of curvature.

These changes are directly relevant to the project's documented v2.3.0 topology failures and collapsed boundary triangles. In the current assessment, 47 atlas targets with an inverse diameter greater than 1 mm involve collapsed boundary-band triangles. The release addresses the underlying type of collapse, but it has not been run on those cases here, and resolution of those targets or the three failed workflows is not established. [Project result-impact assessment](hippunfold_result_impact.md), [PR #587](https://github.com/khanlab/hippunfold/pull/587).

### Atlas, registration and gyrification

- The default unfolded atlas changes from `multihist7` to `multihist7sgi`. The new atlas was rebuilt using the new smoothing-based gyrification index (sGI) and tuned template construction. Its source histology segmentations were corrected for the reversal of dentate source/sink labels 9 and 10. Upstream reported that the older histology dentate PD direction was mirrored relative to its in-vivo examples; this observation concerns the dentate, not the hippocampal PD direction. [Tagged atlas-plugin comparison](https://github.com/khanlab/hippunfold/compare/v2.3.0...v2.4.0), [issue #598](https://github.com/khanlab/hippunfold/issues/598), [new atlas record](https://zenodo.org/records/23843485).
- `gyrification` now means sGI, rather than the previous native-to-unfolded area ratio. The default smoothing scale and pooling sigma are each 1.5 mm. The former measure is separately available as `legacygyrification`; measurements with the same `gyrification` name across versions therefore represent different quantities. [PR #592](https://github.com/khanlab/hippunfold/pull/592).
- Participant-level unfolded registration now uses a directly configured `antsRegistration` SyN stage rather than `antsRegistrationSyNQuick.sh`, with parameters matched to the new atlas construction. For an older atlas such as `multihist7`, the v2.4.0 rule selects the subject's legacy gyrification metric to match that atlas. Explicitly choosing the old atlas does not restore the v2.3.0 surface and registration algorithms. [PR #592](https://github.com/khanlab/hippunfold/pull/592), [v2.4.0 registration source](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/workflow/rules/unfold_reg.smk).

The upstream developers reported substantial sensitivity in intermediate experiments: after a mesh-quality change in their ds002168 example, mean unfolded-registration warp differences were approximately 0.6–0.7 mm and example subfield volumes changed by over 10%. Those numbers compare steps in development and are not estimates of the final v2.4.0-versus-v2.3.0 difference in this cohort. [PR #586](https://github.com/khanlab/hippunfold/pull/586).

## Practical impact on this project's analyses

The saved v2.3.0 products remain the documented results. The project's current HCP assessment reports 163 completed structural workflows and a final functional roster of 162 participants; the release announcement does not change those counts. [Project result-impact assessment](hippunfold_result_impact.md).

For a v2.4.0 reconstruction, use the declared participant inputs and 512-density surfaces with the selected model, template and atlas, and inspect workflow completion and the new surface QC reports. The three previously failed subjects can be processed with the repaired upstream workflow; their success is not established until it runs.

Changed registered surfaces can change sampled fMRI time series and consequently FC, gradients and group atlases. If v2.4.0 is adopted for a cohort-level result, recompute the affected dependent products consistently for that cohort. Production result-tree replacement requires the project's approved path list.

There are also integration changes to account for before a local upgrade: segmentation intermediates use `desc-pred` instead of `desc-nnunet`, the expert model-selection flag is named `--force_tissuepred_model`, and upstream changes model/resource downloads and caching. The release adds surface QC and interactive viewers, as well as per-subfield, area-weighted surface-metric summaries. These features do not establish compatibility with this project's existing runtime adapters or 96-product completion contract. [PR #578](https://github.com/khanlab/hippunfold/pull/578), [PR #595](https://github.com/khanlab/hippunfold/pull/595), [PR #596](https://github.com/khanlab/hippunfold/pull/596), [PR #600](https://github.com/khanlab/hippunfold/pull/600).

## HippLS and HippNeo tissue models

**For the current adult HCP T1w route, use Task101 as the default model.** HippLS is an optional tissue-segmentation model, not a new default or a complete replacement for the unfolding and atlas stages. The original HippUnfold paper reports that its T1w and T2w models used 590 hippocampi for training and 148 for testing, from 369 HCP young adults at 0.7 mm isotropic resolution; both hemispheres of each person stayed in the same split. The authors also illustrate one 7T MP2RAGE T1w epilepsy case, but their 7T manual-atlas evaluation used T2w images. This supports Task101 as a relevant model for adult HCP T1w, not a claim that it is optimal for every T1w scan. [Original HippUnfold paper](https://elifesciences.org/articles/77945), [tagged model configuration](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/config/snakebids.yml).

- HippLS is the `synthtopo_lifespan` model and HippNeo is the separate `synthtopo_neonate` model. Their names indicate intended lifespan and neonatal use, respectively, but the public model records and model PR do not specify a numerical HippLS training age range, training cohort composition, or a head-to-head accuracy comparison with Task101. The PR reports dry-run tests, not a comparative accuracy study. Those sources do not establish that HippLS performs better on this project's adult HCP T1w scans. [HippLS record](https://zenodo.org/records/21112080), [HippNeo record](https://zenodo.org/records/20582534), [model PR #578](https://github.com/khanlab/hippunfold/pull/578).
- The tagged inference rules accept one cropped, coronal-oblique T1w **or** T2w image for either SynthTopo model. The network is a single-input 3D U-Net; both configurations have six levels with feature widths 16, 32, 64, 128, 256 and 512. HippLS has 12 output classes and HippNeo 11. Intensities are scaled to [0, 1] per input before prediction. These code paths do not establish validation across all ages, contrasts, resolutions or field strengths. GPU use is optional; SynthTopo has its own Python/PyTorch environment and checkpoint resource. [Tagged inference rule](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/workflow/rules/pred.smk), [inference implementation](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/workflow/scripts/synthtopo.py), [environment definition](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/workflow/envs/synthtopo.yaml).
- To select HippLS on T1w in a separately prepared v2.4.0 evaluation, add `--force_tissuepred_model synthtopo_lifespan` to `--modality T1w`; use `synthtopo_neonate` to select HippNeo. Without the expert flag, T1w still selects Task101. The opening example in PR #578 uses earlier names, so the tagged configuration is authoritative. [Tagged model configuration](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/config/snakebids.yml), [tagged workflow selection](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/workflow/Snakefile).
- HippLS predicts dentate proximal-distal source and sink labels 9 and 10 and an alveus label 11. In the v2.4.0 label table, 9 is the exposed dentate edge and 10 the buried end; exchanging them mirrors the unfolded dentate. Despite predicting those labels, HippLS explicitly sets `shape_inject: true`: the released default still registers and injects the `upenn` template. For that registration, the configured label list excludes 9–11; the postprocessed segmentation uses the warped template with subject cyst label 7 reinserted where template label 2 permits it. Thus the added predicted labels are not simply passed through unchanged by default. HippNeo also defaults to injection because its model entry leaves the setting unset. The CLI can override either model default, but disabling injection changes the processing and requires evaluation rather than being assumed equivalent. [Tagged label table](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/resources/label_lut/manual_dseg.tsv), [tagged configuration](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/config/snakebids.yml), [shape-injection rules](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/workflow/rules/shape_inject.smk), [tagged workflow](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/workflow/Snakefile).

HippLS is an explicitly selected alternative; the v2.4.0 upgrade does not require changing the model.

## Local implementation readiness at the v2.4.0 upgrade

At that upgrade, the launcher selected v2.4.0 from the environment specification, `multihist7sgi` and density 512, and selected Task101 through the T1w default. Although v2.4.0 also permits explicit `512`, its upstream default is `8k`. The official 2.4.0 release was installed, the resource/GPU adapter was ported to `pred.smk`, and the runtime/CUDA preflight passed. The formal participant outputs at that time used 2.3.0. [Current run contract](../../scripts/core_workflow/lib/hippunfold_run_contract.py), [runtime manifest](hippo2_reproducibility_manifest.md), [tagged prediction rule](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/workflow/rules/pred.smk), [tagged atlas plugin](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/plugins/atlas.py).

The new atlas was present in `runtime/hippunfold_asset_store_shared/hippunfold_assets/atlases/tpl-multihist7sgi` and `atlases_dl/tpl-multihist7sgi`; the two old `tpl-multihist7` cache directories were removed with explicit approval. The selected and extracted new-atlas directories contained the files required at output density 512 and registration density 18k. The `cached-http` plugin and its missing dependencies were installed. A full HCP participant workflow dry run completed with no model or atlas download jobs scheduled. [Runtime manifest](hippo2_reproducibility_manifest.md), [tagged dependency configuration](https://github.com/khanlab/hippunfold/blob/v2.4.0/pyproject.toml).

The then-current [96-product HCP manifest](../../outputs_hcp/inputs/hippunfold/dense_corobl_batch/_batch_logs/output_integrity_manifest.json) named the old `atlas-multihist7` products. The [HCP composition renderer](../../scripts/core_workflow/06_08_render_hcp_subfield_composition.py), [Workbench scene helper](../../scripts/core_workflow/lib/workbench_scene_batch.py), and [multidataset composition renderer](../../scripts/visualize/multidataset_subfield_composition_2mm_2col/render_multidataset_subfield_composition_2mm_2col.py) had been updated to select the new atlas. Formal results at that time remained on the earlier atlas pending approved reconstruction, and their output manifest needed replacement with the new run's actual contract. With CITI168, v2.4.0 retains `desc-unetf3d_dice.tsv` for segmentation QC; the intermediate segmentation itself changes to `desc-pred`. [Tagged prediction rules](https://github.com/khanlab/hippunfold/blob/v2.4.0/hippunfold/workflow/rules/pred.smk).

The HCP preset now selects `--skip-preproc`. The copy records for [sub-102311](../../manifests/raw_copy/sub-102311_copy_manifest.json) and [sub-102816](../../manifests/raw_copy/sub-102816_copy_manifest.json) identify their inputs as HCP `T1w_acpc_dc_restore.nii.gz`. HCP's preprocessing produces the restore image with bias correction, and the [v2.4.0 pipeline guide](https://github.com/khanlab/hippunfold/blob/v2.4.0/docs/pipeline/pipeline.md) recommends `--skip-preproc` for preprocessed HCP data. The directly inspected copy records cover those two subjects; verify the source contract for the remaining cohort before dispatch. Other datasets retain their established settings. [HCP PreFreeSurfer pipeline](https://github.com/Washington-University/HCPpipelines/blob/master/PreFreeSurfer/PreFreeSurferPipeline.sh).
