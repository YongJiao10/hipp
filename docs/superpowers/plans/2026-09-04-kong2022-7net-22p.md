# Kong2022 canonical7 22P source-branch plan

This earlier 22P plan is superseded by the source-only architecture decision.
7net 22P is implemented through the existing numbered core workflow, not a
new driver, utility, or atlas code folder.

The 22P contract remains:

- Stanford: NTHC, TEHC, NTS, NTS Any MDD, NTS Pure MDD, TIS, and TIS PTSD.
- JJ_TMS: HC, Patient, Pure MDD, and Comorbid MDD.
- HCP is excluded because no native HCP 22P input branch exists.
- Stanford consumes the validated `DataOrg_PFM_22P`-derived roots and
  `kong2022_22p` output layout.
- JJ_TMS consumes the validated `shared_inputs_22p` roots and preserves
  `_22p` suffixes in FC, gradient, group-atlas, weighted, and presentation
  outputs.
- Aud is merged into Somatomotor in the canonical7 order.

Use the existing numbered `03_02` extractor/reference step with
`--atlas-slug kong2022_7net` to write the direct `reference/kong2022_7net/`
branch. Run `04_01 --atlas kong2022_7net`, `05_01 --routes routea_7net`, and
the existing numbered `05_02_run_group_atlas.py` with
`--atlases kong2022_7net --network-taxonomy canonical7 --route-tag routea_7net`.
This recomputes canonical7 FC, gradients, spatial clustering, K diagnostics,
K selection, and group labels independently of canonical8. The old
The canonical7 branch is a direct independent branch; it does not reuse another
branch's assignment root. WTA remains limited to the direct Kong2022
`normalized_top20_count` path.

The expected output is four overview PNGs for each of the 11 groups. No new
numbered registry row and no unnumbered core-workflow entrypoint is required.
